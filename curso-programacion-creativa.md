# Programa de la asignatura: Programación Creativa

## Descripción

La asignatura introduce el pensamiento computacional y la programación desde una perspectiva aplicada a la creación, la experimentación y la resolución de problemas. TypeScript y React se emplean como entorno de trabajo para llevar estos fundamentos a interfaces web. Se desarrolla durante 21 semanas, con 36 horas presenciales —16 teóricas y 20 prácticas— y 108 horas de trabajo no presencial, para un total de 144 horas y 3 créditos académicos.

## Objetivo general

Desarrollar habilidades de programación y pensamiento computacional para resolver problemas algorítmicos básicos de manera estructurada, lógica y creativa, utilizando lenguajes y herramientas de programación apropiados.

## Resultados de aprendizaje

Al finalizar el curso, el estudiante podrá:

1. Comprender y aplicar variables, operadores, estructuras de control y funciones para resolver problemas de programación sencillos.
2. Diseñar e implementar programas mediante técnicas de resolución de problemas, verificando la corrección y eficiencia básica de sus soluciones.
3. Descomponer problemas en tareas más pequeñas y aplicar algoritmos para llegar a soluciones efectivas.

## Progresión de aprendizaje

El curso sigue un recorrido único: fundamentos de TypeScript y lógica, práctica guiada, modelado de datos y React, control de versiones, publicación y proyecto final. Cada bloque se apoya en el anterior para que el portafolio crezca de forma gradual.

La algoritmia aplicada se ofrece como profundización opcional una vez que las bases estén firmes. Sirve para retar a quien avanza más rápido sin convertirla en una ruta separada ni en un requisito para continuar.

## Estructura

| Momento | Tema | Foco de trabajo |
|---:|---|---|
| 1 | Introducción a la programación | Relacionar problemas, algoritmos, código, componentes e interfaces. |
| 2 | Fundamentos de programación | Trabajar con datos, decisiones, repeticiones e interacciones simples. |
| 3 | Funciones y modularidad | Separar responsabilidades y construir piezas reutilizables. |
| 4 | Arreglos y estructuras de datos simples | Modelar y transformar colecciones de información. |
| 5 | Resolución de problemas con programación | Diseñar, probar, depurar y explicar soluciones. |
| Transversal | Diagnóstico y proyecto de curso | Conocer el punto de partida, delimitar una idea e integrar aprendizajes en una aplicación o experiencia programable. |

## Metodología

Cada sesión combina explicación breve, demostración, práctica guiada, trabajo aplicado y cierre reflexivo. El estudiante construye progresivamente un portafolio y registra cómo utiliza, revisa y verifica la asistencia de herramientas de IA. Los ejemplos de proyectos orientan el aprendizaje, pero pueden adaptarse a los intereses, ritmo y contexto del grupo.

## Evaluación

La evaluación se organiza de acuerdo con el PIA mediante tres parciales y un proyecto de curso:

- parcial 1: 25 %;
- parcial 2: 20 %;
- parcial 3: 20 %;
- proyecto: 35 %.

Los parciales pueden combinar ejercicios de comprensión, lectura de código, depuración, resolución de problemas y una prueba individual. El proyecto permite integrar los contenidos a través de una aplicación o experiencia programable de alcance acordado.

La [guía docente](guia-programacion-creativa.md#propuesta-complementaria-de-distribución-didáctica) incluye una propuesta complementaria de distribución didáctica para consideración de la coordinación académica. Esta no sustituye la evaluación oficial mientras el PIA mantenga la distribución vigente.

## Cierre del curso

El cierre esperado es un portafolio público o compartible que reúna avances significativos y una aplicación integradora de alcance realista. Puede incluir, entre otros, una calculadora, un conversor, un catálogo, una tiendita, una visualización o una herramienta interactiva.

La selección exacta de actividades y la forma de documentar el proceso puede adaptarse al grupo. Se valorará que el estudiante pueda explicar sus decisiones, mostrar cómo probó su trabajo y reconocer qué aprendió o mejoraría.

## Dedicación por clase

Se proponen 12 encuentros presenciales de 3 horas para cubrir las 36 horas definidas en el PIA. Como estructura de referencia, cada encuentro puede dedicar 30 minutos a explicación, 30 minutos a ejercicio, 60 minutos a laboratorio y una hora adicional a taller, acompañamiento, proyecto o evaluación. El docente puede redistribuir el tiempo ante dificultades técnicas, necesidades del grupo o un debate especialmente valioso. El trabajo no presencial suma 108 horas y combina práctica, lectura, desarrollo, revisión y preparación de los parciales.

## Stack técnico

El stack base será TypeScript, React, Vite, CSS nativo, GitHub y Vercel. Se utilizará la plantilla `react-ts` de Vite para crear una aplicación ligera, mantener una cantidad reducida de dependencias y publicar el trabajo mediante un repositorio conectado a Vercel.

Se recomienda que cada estudiante mantenga un único repositorio de portafolio para reunir avances, ejercicios seleccionados y proyectos. La organización concreta puede variar: los ejemplos de calculadora, catálogo y tiendita son puntos de partida, no una lista obligatoria. La meta es terminar con trabajo funcional, explicable y compartible, idealmente mediante una URL pública.

Para la planificación detallada, consultar la [guía docente](guia-programacion-creativa.md).

Para tutoriales compartibles con el grupo, consultar el [material para estudiantes](material-estudiantes/README.md).

## Condiciones académicas

- Tipo de actividad: teórico-práctica.
- Horas presenciales del docente: 36.
- Relación presencial/no presencial: 1:2.
- Duración: 21 semanas.
- Crédito académico: 3.
- Nota aprobatoria: 3,0.
- Horas de inasistencia con las que se reprueba: 6.
